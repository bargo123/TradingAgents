# Phase 6.2 Ollama Transport Investigation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or superpowers:subagent-driven-development) to execute this plan task-by-task. This is an investigation plan; if the evidence does not prove a transport defect, do not modify production behavior.

**Goal:** Determine whether empty visible Qwen3.5/Ollama responses in Phase 6 originate from thinking-field transport, and change the common provider boundary only if a reproducible transport defect is proven.

**Architecture:** Trace the existing forex quick-model path from role configuration through `TradingAgentsGraph._get_provider_kwargs`, `create_llm_client`, `OpenAIClient`, `NormalizedChatOpenAI`, and Ollama’s `/v1/chat/completions` wire request. Run three isolated qwen3.5:2b probes (current OpenAI-compatible configuration, top-level `reasoning_effort="none"`, and native `/api/chat` `think:false`) with metadata-only capture. A deterministic mock transport guards request-shape semantics; no full graph or MT5 session is created.

**Tech Stack:** Python 3, LangChain OpenAI 1.6.0, OpenAI SDK 3.8.0, Ollama 0.33.3, pytest, Ruff, `compileall`, Git.

**Spec:** Phase 6.2 user request (transport-only investigation; stop before Phase 7).

**Baseline:** `e4d6c545c323d79e9b26ec2aab7bb21084667b35`

## Global Constraints

- Do not run the complete TradingAgents graph or the 40-minute collector.
- Do not modify Bull, Bear, Aggressive Risk, or Neutral Risk prompts.
- Do not change models or remove Ollama/local-model support.
- Do not add MT5 access, execution, orders, or Phase 7 behavior.
- Do not print or persist reasoning/thinking text; capture lengths and scalar metadata only.
- Never promote reasoning/thinking into `response.content`.
- Keep hosted/non-Ollama providers and stock TradingAgents behavior unchanged.
- If no transport defect is proven, stop with an evidence report and make no production fix.

- [ ] **Step 3: Probe C — native Ollama thinking disable**

POST to `/api/chat` with top-level `think:false` and `stream:false`; capture the same metadata only.

- [ ] **Step 4: Classify strictly**

Use only the observed rows: Case 1 (A content zero/reasoning positive while B or C content positive) proves a transport defect; Case 2 (both zero under proper controls) is model/output inadequacy; Case 3 is endpoint/version incompatibility. Do not infer a defect from latency alone.
